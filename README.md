# Миграция Docker-приложений между VDS

Скрипт переносит рабочие Docker-приложения, их Compose-файлы, `.env`, базы данных и остальные данные со старого сервера на новый. Запуск выполняется **на новом сервере**.

Конфигурация рассчитана на конкретную связку: Debian 13, уже установленные 3X-UI и Nginx, приложения из таблицы ниже. Скрипт не является универсальным переносчиком произвольных Docker-проектов: перед использованием на другой конфигурации нужно изменить пути, домены и список образов в `migrate.sh`.

## Что переносится

| Приложение | Каталог на обоих серверах | Домен |
|---|---|---|
| Twitch Drops Miner | `/root/twitch-miner` | `twitch.example.com` |
| Beszel Hub | `/root/beszel` | `status.example.com` |
| Beszel Agent | `/root/beszel-agent` | Отдельный домен не нужен |
| Vaultwarden | `/root/vaultwarden` | `pass.example.com` |
| Lampac | `/opt/lampac-docker` | `lampac.example.com` |

Дополнительно устанавливается Watchtower. Он запускается **последним**, чтобы не обновить образы в середине миграции.

Содержимое `/opt/lampac-docker/cache` не копируется: на новом сервере создаётся пустой каталог кэша.

## Что скрипт не делает

- Не переносит и не заменяет базу данных 3X-UI.
- Не останавливает службу `x-ui`.
- Не изменяет `/etc/nginx/stream-enabled/stream.conf` панели.
- Не меняет DNS-записи панели и Reality.
- Не переносит старые TLS-сертификаты: для приложений выпускаются новые.
- Не исправляет исходные ошибки приложений, например статус `unhealthy` у Twitch Miner.

Пользователей и настройки 3X-UI при необходимости переносите отдельно штатными экспортом и импортом панели.

## Требования

### Новый сервер

- Чистый Debian 13 x86_64.
- Уже установленная и работающая новая 3X-UI.
- Активные службы `x-ui` и `nginx`.
- Установленный Certbot.
- Файл `/etc/nginx/stream-enabled/stream.conf` с директивой:

  ```nginx
  include /etc/nginx/stream-sni.d/*.conf;
  ```

- Свободные локальные TCP-порты `8090`, `8888`, `9090`, `9118`, `45876`.
- Доступ root.

### Старый сервер

- Доступ по SSH; по умолчанию используется пользователь `root` и порт `22`.
- Docker и исходные каталоги из таблицы.
- Возможность установить `rsync`, если его ещё нет.
- Доступ нового сервера к старому по указанному SSH-порту.

Если используется не `root`, этот пользователь должен иметь доступ к Docker и ко всем переносимым файлам. Для описанной конфигурации проще использовать `root`.

## Установка скрипта

### Если репозиторий публичный

Одной строкой скачайте скрипт и установите команду `vds-migrate`:

```bash
curl -fsSL https://raw.githubusercontent.com/oWolkodaWo/vds-docker-migration/main/migrate.sh -o /tmp/vds-migrate.sh && sudo install -m 700 /tmp/vds-migrate.sh /usr/local/sbin/vds-migrate && rm -f /tmp/vds-migrate.sh
```

Проверьте установку:

```bash
sudo vds-migrate --help
```

### Если репозиторий приватный

Обычный `curl` по raw-ссылке без авторизации не сработает. Скачайте `migrate.sh` через авторизованный интерфейс GitHub, скопируйте его на новый сервер и выполните:

```bash
sudo install -m 700 migrate.sh /usr/local/sbin/vds-migrate
sudo vds-migrate --help
```

Не публикуйте в репозитории SSH-ключи, `.env`, Compose-файлы с секретами, базы данных или резервные копии. В GitHub достаточно загрузить `migrate.sh` и `README.md`.

## Порядок миграции

Все команды ниже выполняются **на новом сервере**. После успешного этапа скрипт сам показывает следующую команду.

### 1. Установить зависимости и настроить SSH

```bash
sudo vds-migrate --install-deps
```

Скрипт:

1. Проверит Debian, 3X-UI и Nginx.
2. Установит необходимые пакеты и при необходимости Docker с Compose.
3. Спросит IP старого сервера, SSH-порт, пользователя и путь к ключу.
4. Создаст отдельный ключ Ed25519 и предложит установить его публичную часть на старый сервер.
5. При необходимости предложит установить `rsync` на старом сервере.

При первом подключении может потребоваться подтвердить SSH-отпечаток и один раз ввести пароль старого сервера.

### 2. Выполнить проверки без изменения данных

```bash
sudo vds-migrate --check
```

Проверяются ресурсы, Docker, занятость портов, SSH, наличие исходных каталогов и Compose-файлов. Этот этап только читает данные.

### 3. Посмотреть, что будет скопировано

```bash
sudo vds-migrate --dry-run
```

Это пробная синхронизация `rsync`: файлы не копируются, контейнеры не изменяются.

### 4. Выполнить предварительное копирование

```bash
sudo vds-migrate --sync
```

Данные копируются, пока приложения на старом сервере продолжают работать. Этот этап сокращает последующее время простоя.

Скрипт защищает чужие данные на новом сервере: если каталог назначения уже не пуст и не был ранее создан этим скриптом, синхронизация остановится с ошибкой.

### 5. Переключить приложения на новый сервер

```bash
sudo vds-migrate --cutover
```

Перед продолжением нужно ввести `MIGRATE`.

Скрипт ещё раз синхронизирует данные, загрузит зафиксированные версии образов, остановит пять старых контейнеров, выполнит финальную синхронизацию и запустит приложения на новом сервере. 3X-UI при этом не останавливается.

После успешного запуска старые контейнеры остаются остановленными, чтобы две копии приложений не записывали данные одновременно. Если переключение завершится ошибкой после остановки старых контейнеров, скрипт попытается запустить их обратно.

### 6. Вручную переключить DNS

В панели DNS-провайдера направьте A-записи следующих доменов на IPv4 **нового** сервера:

```text
pass.example.com
twitch.example.com
status.example.com
lampac.example.com
```

Если у этих доменов есть AAAA-записи, обновите их на IPv6 нового сервера или удалите. Не оставляйте AAAA-записи на старом сервере.

Не изменяйте DNS-записи панели и Reality. Дождитесь применения DNS перед следующим этапом.

> Проверка DNS рассчитана на прямые адреса сервера. Адреса прокси Cloudflare она не поддерживает; на время выпуска сертификатов используйте режим «DNS only».

### 7. Выпустить сертификаты и настроить HTTPS

```bash
sudo vds-migrate --tls
```

Скрипт запросит e-mail для уведомлений Let’s Encrypt, если он ещё не сохранён. Затем он:

1. Проверит A/AAAA-записи и запущенные контейнеры.
2. Ненадолго остановит Nginx и выпустит новые сертификаты через Certbot.
3. Сохранит резервные копии изменяемых файлов Nginx в `/root/vds-migration-backups/`.
4. Добавит домены приложений в `/etc/nginx/stream-sni.d/docker-apps.conf`.
5. Создаст отдельные виртуальные хосты приложений, не изменяя `stream.conf` панели.
6. Проверит конфигурацию Nginx и HTTPS каждого домена.
7. Последним установит Watchtower.

Если проверка `nginx -t` не пройдёт, скрипт попытается восстановить прежние файлы приложений из резервной копии.

## Watchtower

Watchtower устанавливается автоматически в конце `--tls`. Отдельная команда для установки или восстановления:

```bash
sudo vds-migrate --watchtower
```

Расписание: каждый день в **03:47 по Asia/Yekaterinburg**.

```cron
0 47 3 * * *
```

Включены очистка старых образов и последовательный перезапуск контейнеров. Конфигурация находится в `/root/watchtower/docker-compose.yml`.

Полезные команды:

```bash
docker ps
docker logs --tail 100 watchtower
docker logs --tail 100 vaultwarden
docker logs --tail 100 lampac
```

## Проверка после миграции

1. Откройте все четыре HTTPS-адреса в браузере.
2. Проверьте вход, существующих пользователей и сессии Vaultwarden.
3. Проверьте данные Beszel и подключение агента.
4. Проверьте работу Lampac и Twitch Miner.
5. Выполните `docker ps` и посмотрите журналы проблемных контейнеров.
6. Некоторое время сохраняйте старый сервер без изменений для возможного отката.

Если после `--tls` браузер или `curl` видит сертификат другого домена, проверьте конфигурацию и полностью перезапустите Nginx:

```bash
sudo nginx -t && sudo systemctl restart nginx
```

## Откат на старый сервер

Откат имеет смысл, пока старый сервер сохранён в состоянии на момент `--cutover`.

1. Остановите приложения на новом сервере:

   ```bash
   sudo docker stop twitch-miner beszel beszel-agent vaultwarden lampac
   ```

2. Верните A/AAAA-записи четырёх приложений на старый сервер.
3. Запустите приложения на старом сервере:

   ```bash
   ssh root@IP_СТАРОГО_СЕРВЕРА 'docker start lampac vaultwarden beszel beszel-agent twitch-miner'
   ```

Не запускайте одновременно старую и новую копии. Если новые приложения уже успели записать важные данные, простой откат вернётся к более раннему состоянию; сначала сохраните и отдельно оцените эти изменения.

## Где хранятся настройки миграции

- Параметры подключения и e-mail: `/root/.vds-docker-migration.conf`.
- Приватный SSH-ключ по умолчанию: `/root/.ssh/vds-docker-migration-ed25519`.
- Резервные копии файлов Nginx: `/root/vds-migration-backups/`.

Эти файлы содержат чувствительную информацию или указывают на неё. Не добавляйте их в GitHub и не передавайте вместе со скриптом.

## Краткая шпаргалка

```bash
sudo vds-migrate --install-deps
sudo vds-migrate --check
sudo vds-migrate --dry-run
sudo vds-migrate --sync
sudo vds-migrate --cutover
# Вручную переключить DNS четырёх приложений на новый сервер.
sudo vds-migrate --tls
docker ps
```
